**Follow-up:** the [correction pass](PS1_PS2_CORRECTIONS_2026-10-21.md) addresses the code findings and adds scoped Flatpak media access. This document records the original findings; its machine state is an audit snapshot, not a current readiness guarantee.

Audit date: 2026-10-21. Inspected current working tree (observed HEAD `983f876`), the real library through read-only SQLite, current emulator configuration/permissions, and a fresh isolated import of the existing PS1/PS2 folders. This audit changes no implementation, game files, BIOS, emulator settings, library entries or historical statistics.

## Machine blockers — verified independently of code review

1. **PS1: no detected DuckStation.** No installed DuckStation Flatpak or PATH command was found; no default DuckStation configuration was present. An isolated CLI launch of the real MGS Disc 1 entry correctly returned `RUNNER_MISSING` before spawning. Current backend family selection does not fall back to PCSX2 for this entry.
2. **PS2: configured BIOS folder is empty.** Installed PCSX2 is Flatpak **v2.8.2**. `inis/PCSX2.ini` specifies `[Folders] Bios = bios`, and `[Filenames] BIOS` is empty. The corresponding `~/.var/app/net.pcsx2.PCSX2/config/PCSX2/bios` exists with no files. Provide/select a BIOS through emulator setup before expecting a retail PS2 boot. No BIOS was downloaded or modified.
3. **PS2: Flatpak cannot read the actual Vice City ISO.** Effective permissions include no grant for this project ROM folder. Confirmed with a `test -r` command inside the installed PCSX2 Flatpak sandbox; result: **not readable**. The check ran a shell only, without starting PCSX2 or changing permissions. A narrowly scoped ROM-folder grant or the managed unpacked runner is needed. Selecting a folder in Marquee does not grant access to another application's sandbox.

These are distinct requirements: adding BIOS does not resolve sandbox access; fixing PS1 labels does not install its emulator. No changes to the user's host setup were made.

## Implementation findings, in priority order

### F1 — P1: every imported PS1 disc is displayed and filtered as PS2

**Locations:** [api/map.ts](../apps/desktop/src/lib/api/map.ts), `pickRunner` and `editionToGame`; [api/contracts.ts](../apps/desktop/src/lib/api/contracts.ts), `LibraryRoot` / `Runner`; [GamePage.svelte](../apps/desktop/src/lib/screens/GamePage.svelte).

`editionToGame` ignores `edition.system`, hardcodes `platform: 'ps2'` and `genre: 'PS2'`, and uses a global PCSX2-preferred runner. Reproduced by passing a PS1 MGS entry and the machine's PCSX2-only runner snapshot to the real mapper: **platform `ps2`, setup `unverified`**, where **platform `ps1`, setup `runner_missing`** is required. PS1 filtering is therefore empty/misleading, while the card offers the wrong emulator/setup context. GamePage's setup actions and labels also assume PCSX2. Merely changing the platform string will leave PS1-specific actions unwired.

The TypeScript contract omits `LibraryRoot.system` and `Runner.kind = 'duckstation'`, so static checking currently cannot express the actual backend contract correctly.

**Correction:** carry system and resolved runner identity through mapping; choose runners per system; add PS1 setup/install affordances and system-aware labels, folder summaries, BIOS hints and title editing. Add snapshot-level tests with both systems and only one installed emulator, then both emulators.

### F2 — P1: a CUE with absent required track files still appears available

**Locations:** [cue.rs](../crates/core/src/cue.rs), `identify_cue`; [library.rs](../crates/core/src/library.rs), `snapshot_media`; [sessions.rs](../crates/core/src/sessions.rs), launch preflight.

Missing CUE data tracks produce an unresolved identity rather than a broken-media diagnostic. Availability checks only whether the `.cue` itself exists; launch preflight consequently does not reject the absent BIN. A disposable `missing.cue` referencing `not-present.bin` imported with **`missing: false`, no warnings**. The problem also applies when required audio files disappear, because the parser only resolves a data track.

**Correction:** validate required CUE references independently from optional identification; retain the library row with an actionable missing-track reason, block Play, and revalidate at launch. An unreadable filesystem or homebrew without a retail serial must remain a separate state.

### F3 — P2: replacing a BIN does not invalidate identification cached for its CUE

**Location:** [library.rs](../crates/core/src/library.rs), `ingest_disc` unchanged-file shortcut.

Only CUE size/mtime participate in the cache decision. On a tiny disposable metadata fixture, changing the BIN's boot serial from `SLUS_007.07` to `SLUS_999.99`, without touching the CUE, left the old serial after rescan. Associated region/artwork can therefore describe previous media. Adding a previously missing BIN also will not trigger identification when the sheet remains unchanged.

**Correction:** include referenced track presence/size/mtime in the CUE dependency fingerprint; invalidate dependent identification/artwork on change. No full-disc hashing is necessary for this check.

### F4 — P2: CUE identification ignores the data track's INDEX offset

**Locations:** [cue.rs](../crates/core/src/cue.rs), `CueTrack`, `parse`, `identify_cue`; [iso.rs](../crates/core/src/iso.rs), reader entry point.

The parser records only whether `INDEX 01` exists, discarding `mm:ss:ff`; the ISO reader always starts at byte zero of the referenced file. Reproduced with a disposable single BIN containing audio followed by a data track at `INDEX 01 00:02:00`: the same metadata resolves when placed at byte zero and fails to identify behind the 150-sector offset. Existing audio-before-data tests check selection of a track, not reading at its actual position.

**Correction:** parse/validate the track offset and honor CUE sector layout when reading. Distinguish a file's track index from logical volume extents. Add end-to-end tests for nonzero starts and multi-file sheets. Current MGS/Silent Hill examples start their data tracks at zero, so their successful identification does not cover this case.

Related limitation: `track_path` drops directories instead of resolving a valid relative subfolder path. Marquee can identify a different path from the one the emulator will read. Enforce one explicit containment/resolution policy, report unsupported references, and do not silently substitute a basename.

### F5 — P2: native/AppImage DuckStation discovery is absent

**Location:** [runners.rs](../crates/core/src/runners.rs), `refresh`.

PS1 discovery only checks the DuckStation Flatpak. There is no native PATH/AppImage/unpacked discovery or managed PS1 installer, despite descriptor hints and documentation mentioning these routes. A temporary executable named `duckstation-qt` on PATH remained undiscovered. The mock executable was never launched.

**Correction:** implement supported DuckStation discovery/setup (and verify its actual packaging), or explicitly constrain onboarding to the supported Flatpak route. Do not offer PCSX2 installation as the remedy for missing PS1 execution.

### F6 — P2: launch attempts are counted as plays even when startup fails

**Locations:** [sessions.rs](../crates/core/src/sessions.rs), `wait_and_finish`; [db.rs](../crates/core/src/db.rs), `complete_session`.

The supervisor unconditionally passes `credit = true` after a spawned process exits, including nonzero exit. Real historical evidence: **Doukutsu has one play / 3 seconds from a failed PCSX2 session; Helengine has two plays / 14 seconds from two failed sessions.** All three recorded sessions exited with code 1. The PS1-through-PCSX2 history predates the current family guard; an isolated current MGS launch correctly refuses that mismatch.

In addition, exit code zero alone marks the runner BIOS `launch_tested`, without observing a game boot. That label overstates the evidence.

**Correction:** distinguish attempted launch, running emulator and verified gameplay/boot state. Retain failed attempt diagnostics while avoiding fabricated successful play counts. Define how a crash after real gameplay should retain time; do not indiscriminately erase all nonzero-exit duration. Reclassify historical statistics only with explicit migration/reconciliation policy, not by resetting this user's library during an audit.

### F7 — P2: adding an existing root under a different system silently ignores the requested system

**Location:** [library.rs](../crates/core/src/library.rs), `add_root` early return for an existing canonical path.

Reproduced in a disposable database: adding a PS1 folder, then requesting that same path as PS2, returns success with the original `system: ps1`. The user receives no mismatch error. This makes correcting an incorrectly categorized folder impossible through the current add flow and allows action labels to disagree with the resulting root.

**Correction:** reject the conflict clearly or provide an explicit reclassification workflow that also handles existing media/edition identities safely. Do not silently reinterpret all existing entries or drop history.

## Further gaps and stale guidance

- MGS discs are separate installations/editions. There is no implemented disc-set identity, M3U playlist or disc-swap flow. Importing both discs is not completion of multi-disc play. Add this after a single-disc live gate, preserving per-disc serials and saves.
- Sonic XA's CHD and CUE representations both import. This is reasonable at the media layer; linking them as alternative installations should be explicit. CHD identity/serial extraction remains unimplemented, so do not promise serial-based CHD covers.
- PS1 onboarding text still says CUE/BIN require conversion even though CUE import now works. Settings and the folder picker remain PS2-centric. `docs/PS1.md` also describes its new CUE support alongside older unsupported-format wording.
- BIOS probing supplies hints and leaves this machine `unverified`; it does not parse the actual configured BIOS selection or expose the confirmed sandbox failure. Improve diagnostics without treating every unresolved default path as proof that a custom BIOS setup is missing.
- Unavailable renderer/gamepad surfaces and actual controller input were not tested. No live boot/exit evidence was produced in this audit.

1. Fix F1 as one vertical change: shared contracts → system-aware mapping → per-system setup actions → mixed-library regression tests. A PS1 entry must stay visible as PS1 and correctly name its missing runner.
2. Fix F2/F3/F4 together around a CUE manifest/dependency model. Test missing/returned tracks, subfolder references, nonzero starts and cache invalidation without copying full images.
3. Complete the actual emulator setup paths: DuckStation support, BIOS selection diagnostics, and narrow Flatpak folder-access handling. Keep the user's existing settings and images intact.
4. Fix F6 statistics/readiness semantics; add failure-before-boot and crash-after-play tests. Handle F7 with an explicit conflict/reclassification decision.
5. Close the **PS2 live gate with Vice City**: correct runner + BIOS + folder access → observed boot → input → exit → duration persisted once → restart → relaunch. Helengine can be an additional smoke test, not a substitute for the retail title.
6. Close the **PS1 live gate with Silent Hill or MGS Disc 1**: setup → observed boot → input → save/exit → duration persisted once → restart → relaunch. Then test MGS Disc 2 and explicit disc switching separately.
7. Refresh PS1/PS2 documentation and the release checklist with observed versions/results; keep unobserved claims pending.
