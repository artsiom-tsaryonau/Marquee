# Game-only windows and headless emulation

Upstream source/docs checked 2026-10-21. These are distinct capabilities:

- **Game-only:** hide the emulator's main/library window; keep the game render window, audio and controller input. This is Marquee's default direction for normal Play.
- **Displayless/headless:** no desktop window. Appropriate for testing or a separately designed streaming/render-capture pipeline. A flag alone does not stream a playable game into Marquee.
- **Save state:** serialized emulated machine state. Hiding a window is unrelated to loading/suspending that state; states are usually tied to a game and emulator version.

| Emulator | Upstream finding | Marquee behavior / remaining work |
| --- | --- | --- |
| PCSX2 | [`-nogui`](https://github.com/PCSX2/pcsx2/blob/master/pcsx2-qt/QtHost.cpp) hides the main window and implies batch; fullscreen still renders the game. | Library argv is now `-batch -fullscreen -nogui -- <disc>`. Setup/BIOS errors can still prevent boot. This is not displayless execution; real launch/exit remains a live gate. |
| DuckStation | [`-nogui`](https://github.com/stenzek/duckstation/blob/master/src/duckstation-qt/qthost.cpp) hides the main window and exits on shutdown. | Existing library argv already uses `-batch -fullscreen -nogui <disc>`. A display and working BIOS are still required. |
| mGBA | Separate [Qt](https://github.com/mgba-emu/mgba/blob/0.10.5/src/platform/qt/main.cpp) and [SDL](https://github.com/mgba-emu/mgba/blob/0.10.5/src/platform/sdl/main.c) frontends; [`-f`](https://github.com/mgba-emu/mgba/blob/0.10.5/src/feature/commandline.c) is fullscreen. SDL takes a game directly without the Qt library interface. | Source pilot builds both. Open selects Qt; `--marquee-sdl -f <game>` selects the game-only frontend through Marquee's wrapper. No GB library adapter or displayless mode is claimed. |
| RPCS3 | [CLI source](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/rpcs3.cpp) distinguishes `--no-gui`, `--fullscreen` (with no-gui) and `--headless`. No-GUI/headless requires a boot target. | Managed standalone tool only. Future PS3 adapter should use no-gui for normal Play, with firmware/game-install checks and lifecycle tests. Headless needs its own renderer/input investigation. |
| Dolphin | [NoGUI frontend](https://github.com/dolphin-emu/dolphin/blob/master/Source/Core/DolphinNoGUI/MainNoGUI.cpp) accepts platform `x11` or `headless`, among platform-dependent choices. [Shared CLI](https://github.com/dolphin-emu/dolphin/blob/master/Source/Core/UICommon/CommandLineParse.cpp) includes boot/user-directory options. NoGUI can still create a game window. | No managed source recipe or library adapter yet. Evaluate a visible Qt/batch or X11 NoGUI path separately from `--platform=headless`. Do not assume a Wayland NoGUI backend exists. |
| Cemu | [LaunchSettings](https://github.com/cemu-project/Cemu/blob/main/src/config/LaunchSettings.cpp) accepts `-g <game>` and `-f` for direct fullscreen boot. | No generic no-GUI/headless option was established from that parser. Standalone tool only; verify actual window/exit behavior before an adapter is marked ready. |
| PPSSPP | [CLI parser](https://github.com/hrydgard/ppsspp/blob/master/Core/CmdLine.cpp) and [SDL frontend](https://github.com/hrydgard/ppsspp/blob/master/SDL/SDLMain.cpp) handle game boot/fullscreen. | Standalone tool only. Direct boot is a candidate for the PSP adapter; do not equate bypassing a menu with displayless operation. Confirm flags against the chosen installed release, not only current master. |
| xemu | [Official CLI](https://xemu.app/docs/cli/) documents `-full-screen`, `-dvd_path <iso>` and `-config_path <config>`. | Standalone tool only; firmware/HDD/EEPROM readiness needs its own adapter. QEMU argument passthrough is documented, but a tested xemu displayless recipe was not established here. |
| Flycast | [Linux entry point](https://github.com/flyinghead/flycast/blob/master/core/linux-dist/main.cpp) and [render/UI loop](https://github.com/flyinghead/flycast/blob/master/core/ui/mainui.cpp) examined. | No verified Marquee game-only/headless recipe yet. Keep standalone status; confirm the release-specific command parser, media formats, BIOS and exit behavior before adding flags. |
| Azahar | [Build configuration](https://github.com/azahar-emu/azahar/blob/master/CMakeLists.txt) examined; frontend and release-packaging details still require targeted validation. | No verified game-only/displayless recipe in this pass. Do not mistake a multiplayer room/server binary for a headless game emulator. Keep standalone status. |

Only the PCSX2 launch change and existing DuckStation adapter are integrated library behavior. Other upstream flags are research, not proof that the installed packaged binary supports them or that a game has been played.

Next implementation: describe launch presentation as adapter capabilities (`game window`, `main UI`, optional `displayless`) rather than applying one “headless” switch to every emulator. Keep a setup/open action available even when normal Play bypasses the main UI. For each new adapter validate boot, stop/exit, focus return, audio/controller input, save persistence, shader-compilation prompts and error visibility. Save-state resume and remote streaming require separate designs and compatibility gates.
